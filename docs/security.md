# Security, retention and provider data flow

- Credentials are read from environment variables, never committed. The app does **not** auto-load `.env`, but DeepEval 4.2.x **does** auto-load `.env`/`.env.local` on import unless `DEEPEVAL_DISABLE_DOTENV=1`. Set it for explicit secret handling and export variables in the process environment or use deployment secrets.
- `PROJECT6_EVAL_URL` requires TLS except localhost, and does not follow redirects; bearer token stays in headers. Never connect an untrusted evaluation bridge.
- The Streamlit front end is not a complete authentication system. Configure `RAGBENCH_ADMIN_TOKEN` for write controls, restrict access with a trusted reverse proxy and provider-side authorization, and expose only over HTTPS. Its unset-token mode is intended for localhost use only.
- Dataset imports are constrained to 5 MiB/10,000 rows; imported JSONL/CSV is parsed, never evaluated as code. Strings and metadata from documents must be treated as data, not trusted instructions. Markdown reports can include untrusted document text; open in a trusted editor.
- Both uploaded labels and raw retrieved passages/answers are saved **without encryption** in SQLite under `RAGBENCH_HOME` (default `./results`). Set filesystem permissions to limit users. Back up and remove files according to your organization's data retention schedule. **No built-in timed purge, delete control or encryption at rest is implemented.**
- External DeepEval judge providers receive the evaluation inputs required by the metric. Faithfulness sends the actual answer and retrieved passages; contextual precision also receives the expected answer. The model/provider is chosen explicitly with `judge_model`, provider credentials via its SDK/environment. **Do not use external evaluation on restricted documents unless authorized.**
- No external cost is asserted where usage and provider pricing are unknown; judge request counts are upper-level counts of metric evaluations, not API tokens or billed requests.
- SQLite records raw text. If exporting CSV into spreadsheet tools, guard formulas before opening; dataset CSV exports escape formulas, but **question score CSV** contains only sanitized fixed identifiers/categories and numeric values from saved runs and should still be handled as untrusted if records are attacker controlled.
- No access audit log/rotation/SSO support is included; implement these in your deployment environment if required.
